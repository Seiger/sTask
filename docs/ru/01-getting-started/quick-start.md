# Быстрый старт

Этот скрипт запускается от чистой установки до первой завершённой задачи без каких-либо вымышленных API.

## 1. Проверь посылку

```bash
cd core
php artisan route:list --path=stask
php artisan stask:worker
```

Вторая команда может вывести `created 0 scheduled task(s), processed 0 task(s)` — это нормальный результат для пустой очереди.

## 2. Обновить реестр работников

Откройте **sTask → Workers** и нажмите кнопку с иконкой `database-cog` (**Обновить реестр работников**). Обнаружение читает `vendor/composer/autoload_classmap.php`, отбрасывает исключённые пространства имён и регистрирует конкретные классы, реализующие `TaskInterface`.

Новый работник становится неактивным. Включите его кнопкой питания или в окне модального редактирования.

## 3. Запускайте вручную

Для активного работника методом `taskMake()` нажмите `player-play`. sTask:

1. создать `s_tasks` со статусом `10`;
2. Запишите первую строку в `storage/stask/{id}.log`;
3. попытается вести `php core/artisan stask:worker` в фоне;
4. будет отображать живой прогресс в строке таблицы с помощью адаптивного HTTP-опроса.

Если `exec`/`shell_exec` отключены, выполните команду вручную:

```bash
php artisan stask:worker
```

## 4. Проверьте результат

На вкладке **Задачи** найдите запись по ID, имени работника или действию. Ожидаемая последовательность статуса:

```text
10 queued → 50 running → 80 finished
```

Статус `30 preparing` определяется моделью и может использоваться кодом приложения, но стандартный `TaskWorker` переходит из прямой очереди на запуск.

Двойной клик по строке открывает модаль только для чтения с сообщением, мета и результатом. Отдельная ссылка на ID находится на вкладке **Logs** и ведёт на полную страницу с деталями задачи.

## 5. Создайте задачу из PHP

Фасад возвращает существующий активный дубликат или новую модель:

```php
<?php

use Seiger\sTask\Facades\sTask;

$task = sTask::create(
    identifier: 'inventory_sync',
    action: 'make',
    data: ['warehouse' => 12, 'force' => false],
    priority: 'normal',
    userId: evo()->getLoginUserID() ?: null,
);

echo $task->id;
```

Важно: `create()` ставит в очередь только на запись. Выполнение требует `stask:worker` или вызова `sTask::execute($task)` в контролируемом процессе.

## 6. Настройте автоматический запуск

В рабочей модале включите Auto Start и выберите расписание. Например, каждый час на 15-й минуте:

```json
{
  "schedule": {
    "enabled": true,
    "type": "periodic",
    "frequency": "hourly",
    "time": "*:15",
    "datetime": "",
    "start_time": "",
    "end_time": ""
  }
}
```

Следующий `stask:worker` создаст будущую очередную задачу с `start_at`. Пока не наступит время, задача видна в **Task**, но не выполняется.

## Чек-лист

- ссылка на исходник пакета соответствует ожидаемой ветке 2.x;
- миграции проходят успешно;
- разрешение `stask` назначение желаемой роли менеджера;
- `storage/stask` веб-пользователь и пользователь CLI доступны для написания;
- cron запускает планировщик каждую минуту;
- рабочий активен, класс существует, идентификатор уникален;
- задача переходит в финальный статус и имеет `finished_at`.
