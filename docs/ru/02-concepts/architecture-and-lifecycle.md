# Архитектура и жизненный цикл

## Компоненты

| Компонент | Ответственность |
| --- | --- |
| `sWorker` | запись логирования работников, класс, активно/скрыто, позиция, настройки JSON |
| `TaskInterface` | минимальные метаданные/UI контрактный работник |
| `BaseWorker` | конфигурация, расписания, создание задач, распределение действий, прогресс и финализация |
| `sTaskModel` | Сохраняемая задача, статус, мета/результат, временные метки и области |
| `TaskWorker` | Создание запланированных задач и последовательное выполнение готовой очереди |
| `TaskProgress` | Живой прогресс только с приложениями в `storage/stask/{id}.log` |
| `WorkerDiscovery` | поиск конкретных классов `TaskInterface` в Composer classmap |
| `WorkerService` | Разрешение, проверка и экземпляры кэша |
| `SupervisorService` | Сериализированная инспекция/запуск/перезапуск долгосрочных процессов |
| EvoUI + Livewire | Таблицы менеджеров, фильтры, модальные окна и прогресс HTTP-опросов |

## Условия

- **Worker** — это класс PHP, который знает, как выполнять одно или несколько действий.
- **Задача** — упорная попытка выполнить действие с определенным идентификатором работника.
- **Action** — это струна, похожая на `make` или `sync_stock`; `BaseWorker` превращает это в `taskMake()` или `taskSyncStock()`.
- **Schedule** — это JSON в `s_workers.settings.schedule`, который `stask:worker` поддерживает следующую очередную задачу.
- **Прогресс** — нестабильный снимок/история в файле `.log`; Поле `s_tasks.progress` не синхронизируется автоматически каждым `pushProgress()`.
- **Метаданные (`meta`)** — нормализованные входные параметры задачи, каст-модель `array`.
- **Результат** — финальная полезная нагрузка или путь, записанный работником; DB тип `LONGTEXT`, литая модель `array`.
- **Сообщение** — короткое сохраняющееся состояние/ошибка в `s_tasks.message`; Живая история хранится отдельно.

## Сотворение

Существует два основных способа:

1. `sTask::create($identifier, $action, $data, $priority, $userId)`.
2. `$worker->createTask($action, $options)` в `BaseWorker`.

Оба нормализуют мета путём рекурсивной сортировки ассоциативных ключей и ищут активные дубликаты по `identifier + action + normalized meta`. Активный статус `10`, `30`, `50`.

Это защищает только от идентичных активных записей. Это не глобальный распределённый замок и не заменяет бизнес-режим.

## Казнь

`stask:worker` следует следующим шагам:

1. читает всех действующих работников;
2. для включенных расписаний, создаёт отсутствующие последующие задачи или выполняет Supervisor Pass;
3. Выбирает все очередные задачи, где `start_at IS NULL OR start_at <= now()`;
4. Для каждой задачи находит запись активного работника и класс;
5. проверяет `TaskInterface`;
6. ставит статус `running`, `start_at = now()`, увеличивает `attempts`;
7. вызывает `invokeAction()`;
8. Если работник не завершил задачу, `finished` устанавливается автоматически;
9. За исключением случаев, он устанавливает `failed` и фиксирует ход ошибок;
10. Если нет активных задач, удаляйте файлы прогресса старше 24 часов.

Текущая команда загружает все готовые очередные строки без лимита пакета и обрабатывается последовательно. Планируйте громкость так, чтобы один проход крона не зависал бесконечно.

## Статус

| Код | Константа | Текст | Значение |
| ---: | --- | --- | --- |
| 10 | `TASK_STATUS_QUEUED` | `pending` | Время ожидания/Рабочий пропуск |
| 30 | `TASK_STATUS_PREPARING` | `preparing` | промежуточное состояние для кода приложения |
| 50 | `TASK_STATUS_RUNNING` | `running` | Действие работает или считается активным |
| 80 | `TASK_STATUS_FINISHED` | `completed` | Успешное финальное состояние |
| 100 | `TASK_STATUS_FAILED` | `failed` | Ошибка или аварийная остановка |

Отдельного статуса отмены не существует. `isFinished()` возвращает `true` только для `80` и `100`.

## Временные метки и продолжительность

- `created_at` — когда была создана запись.
- `start_at` — запланированное время до исполнения, а после `markAsRunning()` — фактическое начало.
- `finished_at` — финализация.
- `updated_at` — последнее изменение, которое зафиксировалось.
- accessor `duration` — секунды от `start_at` до `finished_at`; для выполнения задачи, от `start_at` до настоящего времени.

Из-за двойного значения `start_at` предстоящая очередная задача показывает запланированный старт, а завершённая задача — фактический старт, установленный при запуске.

## Перепробуйте

`markAsRunning()` увеличивает `attempts`. `canRetry()` верно для неудачной задачи, если `attempts < max_attempts`. Однако стандартный `TaskWorker` не возвращает неудачную задачу автоматически в очереди и не имеет отдельной команды повторной попытки. Политика повторных попыток должна быть реализована интегратором или работником. Не обещайте пользователям автоматические рецидиви сразу после `max_attempts = 3`.

## Прогресс и живой интерфейс

`pushProgress()` добавляет одну струну, разделённую по трубе, к `.log`. Наблюдатель JavaScript:

- старт с интервалом в 1,2 секунды;
- увеличивает задержку до 25 секунд, если снимок не меняется;
- проверяется каждые 5 секунд во вкладке скрытый/невидимый;
- не делает параллельные запросы;
- останавливается на `finished`, `failed`, `completed` или после пяти сбоев сети;
- после окончательного статуса просит Livewire обновить поверхность.

Это HTTP-опросы, а не push-транспорт.
