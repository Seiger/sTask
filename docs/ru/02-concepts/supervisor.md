# Супервайзер по процессам

Расписание супервайзера предназначено для отстранённого долгосрочного процесса: слушателя, транспортного демона или другого рабочего времени выполнения. sTask не знает, как проверить PID или пульс конкретного процесса; Это выполняется с помощью адаптера в рабочем классе.

## Контракт

Работник одновременно остаётся обычным `TaskInterface`/`BaseWorker` и добавляет:

```php
use Seiger\sTask\Contracts\SupervisorWorkerInterface;
use Seiger\sTask\Support\SupervisorStatus;

interface SupervisorWorkerInterface
{
    public function supervisorKey(): string;
    public function inspectSupervisor(): SupervisorStatus;
    public function startSupervisor(): SupervisorStatus;
    public function restartSupervisor(): SupervisorStatus;
    public function supervisorStartupGraceSeconds(): int;
}
```

`inspectSupervisor()` не должен менять время выполнения. `startSupervisor()` и `restartSupervisor()` должны быстро вернуться после отдельного запуска; Им не нужно ждать, пока Демон завершит.

## Статус супервайзера

```php
return new SupervisorStatus(
    state: SupervisorState::Healthy,
    pid: 18422,
    heartbeatAt: now()->subSeconds(5),
    startedAt: now()->subHours(3),
    uptimeSeconds: 10800,
    message: 'Listener is receiving updates',
    fingerprint: 'listener:healthy:v1',
);
```

Поля:

- `state` — `healthy`, `starting`, `degraded`, `failed`, `stopped`;
- `pid` — информационный PID, нулируемый;
- `heartbeatAt` — последнее подтверждение жизни;
- `startedAt` и `uptimeSeconds` — время запуска/работы процесса, что отображается в интерфейсе;
- `message` — диагностика, безопасная для менеджера;
- `fingerprint` — стабильный адаптерный отпечаток. Если не указано, sTask хеширует состояние + сообщение.

Не включайте в сообщения/отпечатки токены, секреты сессии или полные командные строки с учетными данными.

## Один пропуск по расписанию

1. sTask получает непустой `supervisorKey()`.
2. Формы `key_hash = sha256(worker_id + ':' + supervisor_key)`.
3. Захватывает блокировку кэша файлов `stask:supervisor:{key_hash}` на 55 секунд.
4. Вызывает проверку только для чтения.
5. Если состояние `stopped`, `degraded` или `failed` и пусковая грация истёк, он вызывает старт/перезапуск.
6. Обновляет `s_supervisor_states`.
7. Создаёт финальную строку задач только для значимых событий: запущено, перезапущено, восстановлено, не выполнено, остановлено, состояние/диагностическое изменение.

Здоровый снимок с тем же отпечатком пальца обновляет только `last_seen_at`, сердцебиение/время работы и `repeat_count`; Новая задача не создаётся каждую минуту.

## Грация старта

`launch_requested_at` помнит последний запрос на запуск. Пока `max(1, supervisorStartupGraceSeconds())` не пройдёт, перезапуск/перезапуск подавляется. После состояния здоровья поле очищается.

Грейс не доказывает, что процесс начался. Адаптер должен правильно различать `starting`, `healthy`, `degraded`, `failed` `stopped` по данным PID/сердцебиения/времени выполнения.

## Переходы и события-задачи

| Наблюдение | Экшн | Задача мероприятия |
| --- | --- | --- |
| Первый `stopped` | `startSupervisor()` | `started`, или `failed/stopped` по статусу возврата |
| Существующие `degraded/failed` | `restartSupervisor()` | `restarted`, или неудача |
| `starting` в Благодати | Запуск не повторяется | Только при смене состояния/отпечатка пальца |
| Нездоровый → `healthy` | состояние сохраняется | `recovered` |
| Состояние изменилось | состояние сохраняется | Событие с новым штатом |
| Отпечаток пальца изменился | Диагностика сохраняется | `diagnostic_changed` |
| здоровый без изменений | Обновление курсора | нет задачи |

Задача события имеет действие `supervisor`, `started_by = 0`, `max_attempts = 1`, временные метки `now()`. Failed/degraded/stop превратилось в статус задачи failed; Другие события — завершено.

## Вкладка «Рабочие»

Для расписания руководителя в таблице показан чип с `activity-heartbeat`. Если штат здоров и `uptime_seconds` известен, значок показывает отформатированное время работы через `niceEta()` вместо слова «Works». Модаль показывает ключ, состояние, PID, сердцебиение, время работы, последний диагноз и время перехода.

## Состояние таблицы и рост

`key_hash` уникальны, поэтому одна строка `worker_id + supervisor_key` обновляется для той же пары. Нормальное сердцебиение не создаёт исторические строки. Таблица растёт только при появлении новых идентификаторов работников/ключей; Автоматической обрезки нет.

После удаления или переустановки рабочих строки в состоянии «сироты» не очищаются внешним ключом, потому что схема не создаёт FK/cascade. Рутинную очистку проводите только после того, как убедитесь, что работник/ключ больше не существует.

## Операционный чек-лист

- запуск отсоединён и быстро возвращается;
- супервизорный ключ стабилен и не пуст;
- Сердцебиение имеет чёткий тайм-аут;
- PID проверяется вместе с идентификатором процесса, а не только `posix_kill($pid, 0)`;
- запуск/перезапуск идемпотентный;
- Благодать больше обычного времени запуска;
- внешний systemd/supervisor не конфликтует с политикой перезапуска адаптера;
- Логи и состояние не содержат секретов.
