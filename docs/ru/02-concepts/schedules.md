# Расписания

Расписание хранится в `s_workers.settings.schedule`. Редактор на вкладке **Workers** нормализует полезную нагрузку в поля `enabled`, `type`, `datetime`, `frequency`, `time`, `start_time`, `end_time`.

## Руководство

```json
{"enabled": false, "type": "manual"}
```

Автоматическая задача не создается. Запуск осуществляется с помощью кнопки менеджера или PHP-кода.

## Однажды

```json
{
  "enabled": true,
  "type": "once",
  "datetime": "2026-07-20 03:30:00"
}
```

`stask:worker` создаёт задачу только если дата-время всё ещё находится в будущем и у работника нет незавершённой задачи. Если время до первого планировщика уже прошло, задача не будет создана.

## Периодические

Поддерживаемые частоты:

| Частота | Поля | Следующий запуск |
| --- | --- | --- |
| `minutely` | Время не требуется | В следующую минуту |
| `every_5min` | Время не требуется | ближайшие минутные кратные 5 |
| `every_15min` | Время не требуется | ближайшие минутные кратные 15 |
| `every_30min` | Время не требуется | ближайшая минута в кратных 30 |
| `hourly` | `time = *:MM` | Следующий час/минута |
| `daily` | `time = HH:MM` | Сегодня или завтра |
| `weekly` | `time`, `days[]` | Следующий выбранный день |
| `monthly` | `time` | текущий день месяца; UI не предоставляет отдельное дневное поле |

Пример каждый день в 02:15:

```json
{
  "enabled": true,
  "type": "periodic",
  "frequency": "daily",
  "time": "02:15"
}
```

Практическое ограничение UI 2.x: модальный режим имеет время, но не показывает редактор `days` для еженедельных и `day` для ежемесячных. Такие значения можно сохранять только через настройки/код JSON; Перед производством проверьте их с настоящей `stask:worker`.

## Обычный в временном окне

```json
{
  "enabled": true,
  "type": "regular",
  "frequency": "every_15min",
  "start_time": "08:00",
  "end_time": "18:00"
}
```

Доступные интервалы: `every_5min`, `every_15min`, `every_30min`, `hourly`. Окно должно находиться в пределах одного календарного дня: если `end_time < start_time`, следующий раз не засчитывается. Ночное окно, как `22:00–06:00` текущей реализации, не поддерживается.

Поиск следующего слота начинается с `start_time` и добавляет интервал до тех пор, пока кандидат не опоздает `now`. После окончания окна функция возвращает `null`; Задание на следующий день не создаётся в этом проходе. Это важное операционное ограничение: в конце дня проверяйте желаемое поведение.

## Супервайзер

`type = supervisor` доступен в модале только для класса, реализующего `SupervisorWorkerInterface`. Он не создаёт задачу проверки здоровья каждую минуту. Планировщик обновляет одну строку живого состояния, а строки задач создаются только для значимых событий жизненного цикла.

Подробности: [Руководитель процессов](supervisor.md).

## Правило одного незавершённого задания

Для одного/периодичного/обычного режима планировщик проверяет задачи work relation с областью `incomplete()` и не создаёт следующую, если есть очередь/готовящая/запущенная запись. Таким образом, длинная или замороженная задача блокирует дальнейшее планирование этого идентификатора.

Экстренная остановка выпускает запись, вставляя её в режим неудачи, но процесс ОС не заканчивается. Сначала установите, продолжается ли процесс, и только затем выполните следующую задачу.

## Расписание Крона и Ларавеля

Провайдер добавляет команду:

```php
$schedule->command(TaskWorker::class)->everyMinute();
```

Это определение не запускает планировщик самостоятельно. Инфраструктура должна выполнять `php artisan schedule:run` каждую минуту или держать `schedule:work` под внешним супервайзером процессов.

## Распространённые ошибки

- **Ничего не создано** — работник неактивен, расписание отключено, нет `taskMake()`, недействительное время или уже есть незавершённая задача.
- **После пропуска** — планировщик впервые увидел дату-время после того, как оно стало прошлым.
- **Еженедельный режим не работает** - `days` массив отсутствует.
- **Обычный режим останавливается вечером** — текущий алгоритм не переносит следующий слот на следующий день.
- **Дубликаты** — несколько `stask:worker` работают параллельно; Дублированная проверка не является атомарным распределённым блокированием.
