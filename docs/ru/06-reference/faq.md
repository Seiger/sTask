# FAQ

## sTask — это Laravel Queue?

Нет. sTask имеет собственные таблицы Eloquent, контракт работника и команду run-and-exit. Он не использует соединение брокер/очередь Laravel в качестве основного движка исполнения.

## Нужен ли мне Редис?

Не для базовой работы. Рабочий кэш/метрики используют Laravel-кэш, а supervisor lock явно забирает `file`. Настроенный кэш приложения должен оставаться в рабочем состоянии.

## Существует ли SSE или WebSocket?

Нет. Живой прогресс — это адаптивная HTTP-конечная точка опроса `/stask/task/{id}/progress`.

## Кнопка «Пуск» выполняет задачу в фоновом режиме?

Контроллер пытается закрыть ответ FastCGI и запустить CLI-рабочий; Резервный режим может быть синхронным или не срабатывать из-за отключённых функций. Cron/планировщик — надёжный производственный путь для производства.

## Останавливает ли экстренный процесс PHP?

Нет. Он переводит запись базы данных только как failed. Процесс ОС должен быть остановлен отдельно.

## Есть ли автоматические повторы?

Нет. Попытки/максимальные попытки сохраняются, но неудачные строки не возвращаются автоматически по стандартной команде.

## Что `system` значит под пользовательским фильтром?

Задачи с `started_by` null или `<= 0`, включая события планировщика/супервайзера.

## Почему фильтр по работе показывает имя, а не идентификатор?

Провайдер разрешает `worker->title` и использует идентификатор только как запасной вариант. Запрос фильтрует задачи по идентификаторам, связанным с выбранными идентификаторами работников.

## Почему задача с той же полезной нагрузкой не была создана во второй раз?

Активное подавление дублирования сравнивает идентификатор, действие и нормализованную мету для статуса в очереди/подготовке/запуске и возвращает существующую модель.

## Безопасно ли подавление дубликатов в расе?

Не полностью. В схеме нет уникального ключа для активного хеша полезной нагрузки. Параллельные процессы могут одновременно проходить через поиск.

## Где хранится прогресс?

`core/storage/stask/{taskId}.log`. `progress` базы данных обновляется отдельно и не отображает автоматически каждый снимок файла.

## Почему нет прогресса, а задача работает?

Ошибки при записи файлов сознательно игнорируются, чтобы не взломать бизнес-задачу. Проверьте разрешения и журналы приложений.

## Как очистить свою историю?

`sTask::cleanOldTasks($days)` удаляет только старые завершённые задачи базы данных. Неудачные задачи, `.log`, загрузки/результаты и состояние супервайзера требуют отдельной политики.

## Как управлять несколькими работниками одновременно?

Текущий CLI не содержит утверждения о атомарном многопроцессном подходе. Не масштабируйте процессы горизонтально без нового дизайна претензий/аренды и идемпотентности.

## Почему обычное расписание не создало задачу на следующий день?

Алгоритм ищет кандидата только в текущем дневном окне и возвращает null за концом. Это известное ограничение текущей реализации.

## Чем расписание Супервайзера отличается от периодического медицинского осмотра?

Супервайзер обновляет одну строку живого состояния каждую минуту и создаёт задачу только для значимого события жизненного цикла. Периодическое расписание поддерживает регулярные очереди `taskMake`.

## У работника убрано состояние супервайзера?

Нет автоматически: отношение не имеет внешнего ключа/каскада базы данных. Ряды сирот убирают после инвентаризации.
